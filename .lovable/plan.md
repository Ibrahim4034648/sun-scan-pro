# البرومبت الشامل الكامل — SPWMS (نظام إدارة ضمان الألواح الشمسية)

انسخ كل ما بين الخطين والصقه في أول رسالة في مشروع Lovable جديد.

---

أنشئ تطبيق ويب/موبايل احترافي كامل باسم **"SPWMS – Solar Panel Warranty Management System"** / **"نظام إدارة ضمان الألواح الشمسية"** لإدارة ضمانات الألواح الشمسية ميدانياً، بواجهة عربية RTL أولاً (mobile-first)، جاهز للتحويل إلى APK ويعمل **دون إنترنت**.

## 1) التقنيات
- TanStack Start + React 19 + TypeScript + Vite 7 + Tailwind v4 + shadcn/ui.
- Lovable Cloud للمصادقة وقاعدة البيانات و RLS.
- Capacitor (Android/iOS) + أذونات الكاميرا والتخزين.
- html5-qrcode للمسح، xlsx-js-style + jsPDF + html2canvas للتصدير.

## 2) الهوية البصرية
- الأساسي برتقالي `#FF8A00`، الداكن `#0F141B`، خلفية رمادية ناعمة.
- خطوط: Space Grotesk للعناوين، Inter/Cairo/Tajawal للنصوص العربية.
- شعار: درع + لوح شمسي + صاعقة (SVG).
- كل الألوان عبر semantic tokens في `src/styles.css` — لا ألوان ثابتة داخل المكوّنات. وضع فاتح وداكن.

## 3) تدفّق الشاشات
1. `/` **شاشة البداية (Splash)** — تظهر لغير المسجّلين فقط: صورة هوية كاملة، أيقونات الميزات (Scan / Manage / Track / Report)، زر «إنشاء حساب» → `/auth?mode=signup`، زر «تسجيل الدخول» → `/auth?mode=login`. دعم `viewport-fit=cover` و safe-area. المسجّل يُحوَّل تلقائياً إلى `/welcome`.
2. `/auth` — تبويب بريد/كلمة مرور + زر **الدخول عبر Google** (فعّل مزوّد Google). مهم: `redirect_uri = window.location.origin` فقط (لا مسار محمي) لتفادي خطأ `State verification failed`، ثم التوجيه إلى `/welcome` بعد تأكيد الجلسة. الجلسة تُحفَظ فيبقى المستخدم داخلاً (تسجيل دخول مرة واحدة).
3. `/welcome` — تظهر في كل تشغيل: ترحيب باسم المستخدم + زر كبير «الانتقال إلى المشاريع».
4. `/app` — التطبيق الرئيسي: شاشة المشاريع ثم شاشة تفاصيل التركيب والمسح.
5. `/privacy` — سياسة الخصوصية (مطلوبة لمتجر Google Play).

## 4) شاشة المشاريع (أول شاشة داخل التطبيق)
- بطاقات (بكسات) للمشاريع الموجودة + زر «+ إضافة مشروع جديد».
- المودال يطلب: اسم المشروع، العميل، تاريخ التركيب (وتُحذف هذه الحقول من نموذج تفاصيل التركيب).
- اختيار مشروع يفتح شاشة المسح مع شريط أعلى يعرض المشروع النشط + زر رجوع. كل لوح مرتبط بمشروعه.

## 5) نموذج تفاصيل التركيب
الحقول: الرقم التسلسلي (بالماسح أو يدوياً)، **موديل اللوح** (قائمة + خيار «موديل جديد»)، **مكان اللوح في المجموعات الشمسية St1…St10** (بديل حقل مدة الضمان المحذوف)، الموقع، تاريخ التركيب، ملاحظات.
- القوائم القابلة للتوسيع: العميل / المشروع / الموقع / الموديل — عند اختيار «إضافة جديد» يظهر حقل نصي مع **زر حفظ وزر إلغاء**، والقيمة تُخزَّن وتظهر في القائمة لاحقاً.
- منع تكرار الأرقام التسلسلية + إبراز المكرر.

## 6) الماسح الذكي
- كاميرا خلفية افتراضياً، دعم QR + CODE_128 + CODE_39 + EAN_13 + UPC_A + DataMatrix.
- زر فلاش، تبديل كاميرا، صوت/اهتزاز عند النجاح، منع تكرار القراءة خلال ثانيتين، إطار مسح متحرك.
- رسائل خطأ عربية واضحة لكل من: HTTPS مطلوب، متصفح غير مدعوم، `NotAllowedError`, `NotFoundError`, `NotReadableError`, `OverconstrainedError`.

## 7) شاشة الأذونات (قبل تشغيل الماسح)
Overlay بخطوتين وشريط تقدّم:
- **خطوة 1 — الكاميرا:** شرح «لقراءة الأرقام التسلسلية»، زر «أوافق» ينفّذ `getUserMedia({video:{facingMode:{ideal:'environment'}}})` فعلياً مع حالة تحميل.
- **خطوة 2 — التخزين:** شرح «لحفظ تقارير Excel/PDF والنسخ الاحتياطية»، اختبار عبر `Filesystem.readdir`.
- حفظ الموافقة في `localStorage` (`spwms_perm_consent_v2`) وعدم إعادة السؤال. تشغيل الماسح محجوب حتى القبول.

## 8) جدول السجلات
أعمدة: # | الرقم التسلسلي | مجموعة String | الموديل | الموقع | التاريخ | ملاحظات | إجراءات.
- بحث لحظي، فرز، إبراز المكرر، بطاقات قابلة للتوسّع على الموبايل، حذف عنصر.

## 9) العمل دون إنترنت (Offline-first)
- كل عملية (إضافة مشروع/لوح، حذف) تُكتب فوراً في التخزين المحلي ثم تُدفَع للسحابة.
- **طابور مزامنة** يحتفظ بالعمليات المعلّقة ويُفرَّغ تلقائياً عند حدث `online` وكل 30 ثانية.
- **Hydrate from cache** عند الإقلاع قبل جلب البيانات الطازجة.
- **مؤشر حالة عائم** يعرض متصل/غير متصل وعدد العمليات المنتظرة.

## 10) قاعدة البيانات
- `profiles` (id, full_name, phone, created_at) + Trigger `handle_new_user` لإنشاء الملف وإسناد دور `user`.
- `projects` (id, user_id, project_name, customer_name, customer_phone, location, install_date, notes, created_at).
- `panels` (id, project_id, user_id, serial, model, string_group, location, install_date, notes, created_at) + قيد فريد على (project_id, serial).
- `user_roles` مع enum `app_role` ودالة `has_role` (security definer) — الأدوار في جدول منفصل حصراً.
- RLS مُفعَّل: كل مستخدم يرى بياناته فقط، والأدمن يرى الكل. **GRANT** لكل جدول لـ `authenticated` و `service_role`.

## 11) الأمان
- بوابة مصادقة قبل عرض أي شاشة بيانات.
- Escape/تنقية لكل قيمة يدخلها المستخدم قبل إدراجها في HTML (خصوصاً قوالب التقارير) لمنع XSS.
- التحقق من نوع وطول أي بيانات مستوردة من JSON.
- عدم إظهار رسائل أخطاء قاعدة البيانات للمستخدم — رسائل عربية عامة + `console.error` للمطوّر.

## 12) تقارير التصدير (PDF + Excel) — احترافية
قالب مستند رسمي A4:
- **Header:** شعار الشركة، اسم الشركة، عنوان «Solar Panel Warranty Report / تقرير ضمان الألواح الشمسية»، شريط برتقالي.
- **شبكة معلومات:** اسم العميل، الجوال، المشروع، الموقع، تاريخ التركيب، تاريخ الإصدار.
- **الجدول:** No | Serial | String Group | Model | Notes.
- **الملخص:** إجمالي الألواح، عدد المجموعات، مدة الضمان.
- **Footer:** توقيع الفني، توقيع العميل، مكان الختم، ترقيم صفحات تلقائي.
- PDF: تحميل خط Cairo قبل الرسم ثم `html2canvas` + تقسيم صفحات دقيق لضمان عرض العربية بلا قطع.
- Excel: `xlsx-js-style` بخلايا مدمجة، RTL، صفوف مخطّطة، وشُرَط توقيع.
- التصدير يحترم الفلاتر النشطة (مشروع/عميل).

## 13) Capacitor / APK
- `appId: app.lovable.spwms`, `appName: SPWMS`.
- أذونات `AndroidManifest.xml`: CAMERA, INTERNET, VIBRATE, READ_MEDIA_IMAGES.
- `src/lib/native-permissions.ts` يطلب أذونات الكاميرا والتخزين عند الإقلاع على الأجهزة الأصلية فقط (no-op على الويب).
- ملف `APK_BUILD.md` بخطوات: `bun install && bun run build && npx cap sync android && npx cap open android` ثم توليد AAB موقّع والنشر على Google Play.

## 14) SEO & Meta
لكل صفحة `head()` خاص: عنوان < 60 حرفاً، وصف < 160، og:title/og:description/og:type/twitter:card. عنوان الرئيسية: «SPWMS – Solar Panel Warranty Management».
